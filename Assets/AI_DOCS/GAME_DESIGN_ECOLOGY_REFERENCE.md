# 地下生态型 2D 像素游戏：设计规范与参考基准

> 本文档用于放入 Unity 项目中，作为 AI Agent、开发者和后续设计讨论的共同参考。  
> 目的不是完整复刻《勇者のくせになまいきだ。》，也不是照搬 Wiki 数值，而是从其 Wiki 与资料中抽象出适合本项目使用的设计原则、系统关系和判断标准。

---

## 0. 文档定位

### 0.1 本文档是什么

本文档是一个**项目级游戏设计规范**，用于补足当前项目在整体设计抽象层面的不足。

它回答的问题包括：

- 这个游戏的核心乐趣是什么？
- 地下城为什么不是普通塔防地图？
- 土块、养分、魔分、怪物、勇者之间是什么关系？
- 玩家到底在控制什么？
- 怪物 AI 应该复杂还是简单？
- 后续 AI Agent 在设计和实现功能时，应该遵守哪些方向？
- 当没有设计头绪时，可以回到哪些 Wiki 页面查找参考？

### 0.2 本文档不是什么

本文档不是：

- 具体代码实现说明。
- 单一怪物的规格书。
- 完整数值表。
- 原作攻略复刻文档。
- 商业项目最终 GDD。

因此，本文档中不会规定具体类名、函数名、组件结构或完整数值公式。  
它更像是一个“设计北极星”：当项目方向开始混乱时，用它判断系统是否仍然围绕地下生态循环展开。

## 1. 核心设计概念

### 1.1 一句话概念

玩家不是直接操作怪物战斗，而是通过挖掘地下空间、引导资源流动、构建食物链与魔物生态，来抵御从地表入侵的勇者。

### 1.2 设计关键词

- 地下生态
- 间接控制
- 资源循环
- 食物链
- 地形诱导
- 低智能个体
- 高复杂度群体涌现
- 魔王防卫
- 土壤经营
- 勇者入侵
- 死亡回流
- 玩家误操作也能产生后果

### 1.3 与普通塔防的区别

本项目不应被设计成普通塔防：

| 普通塔防 | 本项目目标 |
|---|---|
| 玩家直接放置防御塔 | 玩家挖掘土块，间接生成生态 |
| 单位主要负责攻击 | 单位首先是生态系统的一部分 |
| 怪物/塔职责固定 | 怪物会进食、死亡、繁殖、转化资源 |
| 地图多为路径规划 | 地图本身是资源容器和生态场 |
| 防御成功依赖火力堆叠 | 防御成功依赖生态是否稳定 |

本项目的重点不是“把敌人打死”，而是“让地下生态在敌人入侵前形成可以自我维持的结构”。

## 2. 设计支柱

### 2.1 支柱一：玩家通过地形间接控制生态

玩家的主要行为是挖掘，而不是直接命令怪物。

玩家可以影响：

- 怪物在哪里诞生。
- 怪物如何移动。
- 资源流向哪里。
- 食物链在哪里形成。
- 勇者会经过怎样的路线。
- 魔王被发现和抓走的风险。

玩家不应该随时随地直接命令怪物“去攻击某人”或“去搬运某物”。  
如果怪物太听话，游戏就会失去“地下生态模拟”的核心特征。

### 2.2 支柱二：土块不是墙，而是资源容器

土块在本项目中不是普通障碍物。

每个土块至少在概念上承担三层意义：

1. **空间结构**：决定可通行区域与路线。
2. **资源容器**：保存养分、魔分等能量。
3. **生成媒介**：被挖掘时可能产生不同类型的魔物或特殊结构。

因此，“挖一块土”不是单纯打开道路，而是一次对地下生态的干预。

### 2.3 支柱三：资源循环比单体战斗更重要

怪物可以战斗，但战斗不是唯一价值。  
一个怪物死亡后，其持有的资源应当重新影响土壤、其他怪物或后续生成。

设计时应优先思考：

- 它从哪里获得资源？
- 它把资源带到哪里？
- 它死后资源去哪？
- 它是否被其他怪物吃掉？
- 它是否能帮助更高级魔物出现？
- 它是否破坏了生态平衡？

### 2.4 支柱四：个体低智能，整体高复杂度

许多基础怪物不需要复杂寻路。  
它们可以只具备非常简单的规则：

- 直线移动。
- 碰墙转向。
- 遇到食物才改变行为。
- 饥饿时寻找附近目标。
- 满足条件后繁殖或变形。

复杂性应该来自：

- 地形。
- 数量。
- 资源分布。
- 食物链。
- 勇者入侵。
- 玩家挖掘造成的连锁变化。

不要用“聪明 AI”替代“系统涌现”。

### 2.5 支柱五：勇者既是威胁，也是资源输入

勇者不是单纯的敌人。  
勇者进入地下城会破坏生态、杀死怪物、抓走魔王，但勇者死亡后也会给地下城带来新的养分或魔分。

因此，勇者是：

- 防卫目标的压力源。
- 地下城生态的破坏者。
- 后续资源循环的补给源。
- 推动阶段升级的外部事件。

### 2.6 支柱六：可读性优先于复杂度

本项目是 2D 像素游戏，系统可以复杂，但玩家必须看得懂。

必须尽量可视化：

- 土块中是否有养分。
- 土块中是否有魔分。
- 哪些土块更适合生成魔物。
- 怪物当前是否携带资源。
- 怪物是否饥饿。
- 食物链是否断裂。
- 勇者路线是否接近魔王。
- 死亡后资源是否回流到土中。

如果系统复杂但看不见，玩家会认为结果是随机的。

## 3. 核心游戏循环

### 3.1 基本循环

推荐的基础循环如下：

1. 玩家观察地下土块分布与资源状态。
2. 玩家消耗有限行动资源挖掘土块。
3. 被挖开的土块根据资源状态生成基础魔物或特殊结构。
4. 魔物开始移动、进食、繁殖、死亡。
5. 地下资源在土块、魔物、尸体、勇者之间循环。
6. 玩家继续调整地下地形，让生态向有利方向发展。
7. 勇者从入口入侵。
8. 勇者沿路径探索、战斗、寻找魔王。
9. 魔物群落与勇者发生冲突。
10. 勇者死亡或魔王被抓。
11. 战斗结果改变资源分布，进入下一阶段。

### 3.2 核心体验目标

玩家应该经历这样的心理过程：

- “我挖开这里，会生成什么？”
- “这条通道会不会让资源集中？”
- “这只怪物虽然弱，但它能喂养后面的怪。”
- “我是不是把食物链挖断了？”
- “勇者快来了，我的生态还没成型。”
- “这个区域资源太分散，需要重新引导。”
- “怪物死了不是完全损失，它还能回到土里。”
- “我刚才的地形设计让怪物自然形成了防线。”

## 4. 地图与土块系统规范

### 4.1 地图结构

地图应被理解为一个二维地下生态场。  
地表入口位于上方，魔王或核心目标位于地下某处。  
玩家通过挖掘使原本封闭的土层逐步变成连通空间。

推荐地图包含：

- 地表入口。
- 可挖掘土层。
- 不可挖掘边界。
- 不同资源密度的土块。
- 魔王房间或核心房间。
- 可形成循环路线的地下空间。
- 可形成死路、巢穴、陷阱的局部结构。

### 4.2 土块的设计意义

土块不只是格子。  
一个土块至少应具有以下抽象属性：

- 是否已被挖开。
- 是否可被挖开。
- 养分倾向。
- 魔分倾向。
- 土壤等级或资源等级。
- 是否能生成魔物。
- 是否能生成特殊结构。
- 是否处于危险区域或关键路径上。

这些属性不一定都要在第一版实现，但设计上应保留扩展空间。

### 4.3 挖掘行为的意义

挖掘行为同时改变：

- 通行空间。
- 勇者路线。
- 怪物移动路线。
- 资源暴露方式。
- 怪物生成结果。
- 生态循环效率。

因此，AI Agent 后续实现功能时，不应把“挖土”写成单纯删除 tile。  
它应该被视为整个系统的触发点。

## 5. 资源系统规范

### 5.1 养分

养分是地下生态的基础资源。  
它主要支持低阶到中阶生物链的形成。

设计作用：

- 生成基础魔物。
- 通过基础魔物搬运。
- 通过捕食向上转移。
- 通过死亡回到土中。
- 支撑后续更高阶生物出现。

养分的设计重点不是“数值越高越强”，而是“如何流动、集中、转移和回收”。

### 5.2 魔分

魔分可以理解为更稀有、更偏魔法或特殊系统的资源。  
它不应像养分一样到处均匀存在，而应通过勇者、魔法行为、死亡、特殊结构等方式进入地下城。

设计作用：

- 生成魔法系魔物。
- 激活特殊结构。
- 影响勇者 MP 或技能。
- 支撑高阶或特殊防卫手段。
- 形成区别于养分链的第二套生态逻辑。

### 5.3 资源守恒感

原作资料中存在“养分/魔分大体循环、死亡后回到土中、捕食后转移到捕食者”等思想。  
本项目不必严格数学守恒，但需要让玩家感受到：

- 资源不是凭空乱刷。
- 怪物死亡不是完全消失。
- 捕食不是单纯删除单位。
- 勇者死亡会改变地下生态。
- 土块是资源的最终沉积场之一。

### 5.4 资源流动路径

推荐抽象为：

```text
土块 → 基础魔物 → 捕食者 → 高阶魔物
  ↑         ↓          ↓
  └──── 死亡/枯萎/排泄/尸体回流 ────┘

勇者 → 死亡 → 养分/魔分进入土块或尸体
勇者 → 魔法/技能 → 魔分影响局部环境
```

注意：这只是设计示意，不是代码实现。

## 6. 魔物系统规范

### 6.1 魔物不是兵种，而是生态角色

每类魔物都应优先定义“生态角色”，再定义战斗能力。

建议用以下问题描述每类魔物：

- 它从哪种土或结构中出现？
- 它吃什么？
- 它会被谁吃？
- 它如何移动？
- 它如何繁殖或转化？
- 它死亡后对土壤有什么影响？
- 它对勇者的威胁是什么？
- 它对生态系统的价值是什么？
- 它是否容易失控？
- 玩家如何通过地形间接影响它？

### 6.2 基础搬运者

基础搬运者负责让资源开始流动。  
它们战斗能力可以很低，但生态价值很高。

设计目标：

- 低成本出现。
- 移动规则简单。
- 能搬运或改变土块资源。
- 是更高阶魔物的食物或前置条件。
- 数量多时形成生态基础。

设计风险：

- 如果太弱且没有资源价值，玩家会忽视。
- 如果太强，玩家会把它当普通战斗单位。
- 如果移动太聪明，玩家会失去通过地形诱导的乐趣。

### 6.3 初级消费者

初级消费者以基础搬运者或低阶资源为食。  
它们是食物链真正开始成型的标志。

设计目标：

- 通过吃低阶单位积累资源。
- 数量可自然增长。
- 能对勇者产生一定威胁。
- 过量时会破坏底层生态。
- 过少时无法支撑上层魔物。

设计重点：

- 饥饿、捕食、繁殖三者需要形成可读循环。
- 玩家应能理解“不是怪越多越好，而是比例要对”。

### 6.4 中阶战斗者

中阶战斗者是地下城对勇者的主力防卫单位。  
它们通常依赖前面的食物链或高资源土块出现。

设计目标：

- 对勇者有明确伤害。
- 数量不应过度泛滥。
- 出现需要生态准备。
- 死亡后能将资源回收到土壤。
- 可能反过来吃掉低阶生态，造成系统压力。

### 6.5 魔法系单位

魔法系单位应围绕魔分展开，而不是简单复制养分系。

设计目标：

- 稀有。
- 功能特殊。
- 与勇者 MP、技能或魔法行为产生关系。
- 可作为后期策略分支。
- 不完全依赖传统食物链。

魔法系单位可以承担：

- 远程攻击。
- 异常状态。
- 资源转化。
- 区域效果。
- 辅助防御。
- 干扰勇者行动。

### 6.6 支援型单位

支援型单位不一定直接攻击勇者。  
它们可以通过存在本身改变战局。

可能职责：

- 提升周围魔物防御。
- 降低勇者能力。
- 储存资源。
- 转换资源。
- 修复生态。
- 作为特殊食物。
- 触发地形效果。

支援型单位适合用于增加生态系统深度，但不应让玩家完全依赖单一支援堆叠。

### 6.7 高阶单位

高阶单位是玩家成功经营生态后的奖励，但也应是资源压力源。

设计目标：

- 明显强于普通单位。
- 出现成本高。
- 需要资源链支持。
- 不应轻易量产。
- 可能破坏低阶生态平衡。
- 死亡后产生巨大资源回流或风险。

高阶单位不是单纯“越多越好”，而应让玩家思考是否养得起。

## 7. 食物链规范

### 7.1 食物链是项目核心之一

食物链的作用不是模拟真实自然，而是让玩家理解：

- 弱小单位有长期价值。
- 强大单位需要生态基础。
- 杀死或吃掉一个单位会改变资源流。
- 玩家不能只追求短期战斗力。
- 地下城强度来自循环，而不是堆数值。

### 7.2 捕食的设计意义

捕食不应只是“删除一个单位并回血”。  
捕食应至少在概念上完成资源转移：

```text
被捕食者持有的资源 → 捕食者体内
```

这会带来几个设计结果：

- 强者变强。
- 底层被吃光会导致生态断裂。
- 捕食者过多会饿死。
- 死亡位置会影响资源回流。
- 玩家需要通过地形控制捕食密度。

### 7.3 饥饿与过量

如果项目加入饥饿系统，应遵守以下原则：

- 饥饿不是惩罚玩家，而是让生态有维护成本。
- 强单位越多，底层供给压力越大。
- 饥饿死亡后资源回流，给系统二次机会。
- 玩家可以通过间接方式调节数量，而不是直接删除单位。

### 7.4 生态失衡

本项目应该允许生态失衡，因为失衡本身是学习内容。

常见失衡包括：

- 底层单位过少，高阶单位饿死。
- 底层单位太多，战斗力不足。
- 捕食者太多，把食物链吃断。
- 魔分过多但缺乏利用方式。
- 资源集中在错误位置。
- 勇者死在没有土块承接资源的位置。
- 玩家挖出过于直接的勇者路线。

这些都可以成为玩家逐步理解系统的反馈。

## 8. 勇者系统规范

### 8.1 勇者的设计定位

勇者是外部扰动。  
他/她的作用不是单纯提供战斗目标，而是测试玩家地下生态是否稳定。

勇者应具有以下作用：

- 从入口进入地下城。
- 探索路径。
- 攻击魔物。
- 使用技能或魔法。
- 寻找魔王或核心目标。
- 破坏玩家正在形成的生态。
- 死亡后向地下系统注入资源。

### 8.2 勇者路线

勇者路线应当受地形影响。  
玩家挖掘得越直接，勇者越容易接近目标；玩家挖掘得越复杂，生态更容易成型，但资源和怪物移动也可能变得低效。

因此，路线设计应形成取舍：

- 直线通道利于怪物移动，但也利于勇者深入。
- 复杂迷宫能拖延勇者，但可能阻断资源流。
- 大空间利于群体聚集，但也可能让勇者快速清场。
- 死路能积累资源，但也可能变成生态孤岛。

### 8.3 勇者能力

勇者能力应逐步升级，并针对玩家生态提出不同问题。

可能的勇者类型：

- 近战型：测试前线战斗力。
- 魔法型：测试魔分应对与远程威胁。
- 高速型：测试路线与拦截能力。
- 高防型：测试持续输出与资源储备。
- 回复型：测试爆发能力或 MP 干扰。
- 召唤型：测试生态稳定性。
- 探索型：测试魔王房间隐藏与路径设计。

### 8.4 勇者死亡的价值

勇者死亡后应当改变地下资源格局。  
这让“击败勇者”不只是过关条件，也是后续发展的资源来源。

推荐设计：

- 勇者死亡位置附近土块获得资源。
- 勇者的 MP 或魔法能力转化为魔分。
- 勇者尸体可成为特殊生态节点。
- 高级勇者死亡后提供更高价值资源。
- 如果死亡位置附近没有可承接土块，资源部分流失。

---

## 9. 玩家操作规范

### 9.1 玩家身份

玩家不是传统意义上的角色。  
玩家更像地下城的破坏神、生态设计者或间接导演。

玩家可以做：

- 挖掘土块。
- 打开道路。
- 诱导怪物移动。
- 制造生成条件。
- 调整勇者路线。
- 安排魔王或核心位置。
- 在有限规则内干预生态。

玩家不应主要做：

- 直接操控怪物移动。
- 直接选择怪物攻击目标。
- 像 RTS 一样框选单位。
- 像塔防一样随意购买固定防御塔。
- 无成本删除不想要的生态结果。

### 9.2 玩家资源限制

为了让挖掘有意义，应存在某种限制：

- 挖掘次数。
- 挖掘能量。
- 时间压力。
- 阶段限制。
- 地层限制。
- 危险区域限制。

限制的目的不是束缚玩家，而是让每次挖掘都成为设计判断。

### 9.3 操作反馈

每次玩家操作都应给出明确反馈：

- 这块土为何生成这个单位。
- 这条路为何改变了怪物运动。
- 资源为何流向这里。
- 勇者为何选择这条路。
- 魔物为何死亡或饥饿。
- 魔王为何被发现。

如果玩家无法理解结果，就无法学习系统。

---

## 10. 关卡与节奏规范

### 10.1 单局节奏

推荐单局由三段构成：

#### 准备阶段

玩家观察地图并挖掘初始生态。  
目标是让基础资源开始流动。

#### 入侵阶段

勇者进入地下城。  
玩家观察生态与勇者冲突，必要时继续挖掘或微调。

#### 结算阶段

勇者死亡或魔王被抓。  
系统根据剩余生态、资源循环、死亡回流等结果进入下一局或下一阶段。

### 10.2 教学顺序

建议按以下顺序逐步引入系统：

1. 挖土生成基础魔物。
2. 基础魔物会移动。
3. 土块中有养分。
4. 养分会被搬运。
5. 怪物会被吃。
6. 捕食会转移资源。
7. 怪物死亡后资源回到土中。
8. 勇者会沿通道入侵。
9. 勇者死亡会带来资源。
10. 魔分与特殊单位出现。
11. 支援单位与高阶单位出现。
12. 生态失衡成为主要挑战。

### 10.3 难度提升方式

难度不应只靠勇者数值膨胀。  
更推荐通过以下方式提升：

- 勇者类型变化。
- 入侵时间缩短。
- 地图资源分布更偏。
- 魔王位置更危险。
- 地层结构更复杂。
- 特定资源稀缺。
- 食物链更容易断裂。
- 勇者技能针对特定生态。
- 玩家挖掘资源更紧张。

## 11. 视觉与信息设计规范

### 11.1 像素风格目标

本项目使用 2D 像素风格。  
视觉不应只追求还原，而应服务系统可读性。

优先级：

1. 玩家能看懂格子状态。
2. 玩家能看懂资源差异。
3. 玩家能看懂怪物状态。
4. 玩家能看懂勇者威胁。
5. 玩家能看懂生态变化。
6. 最后才是装饰细节。

### 11.2 土块表现

土块应通过颜色、纹理或小图标表现不同资源倾向。

例如：

- 普通土。
- 低养分土。
- 高养分土。
- 魔分土。
- 混合资源土。
- 特殊结构土。
- 不可挖掘土。

不要让所有土块看起来几乎一样，否则玩家无法进行生态判断。

### 11.3 怪物状态表现

怪物应能表现：

- 是否携带资源。
- 是否饥饿。
- 是否即将繁殖。
- 是否受伤。
- 是否处于特殊状态。
- 是否正在捕食。
- 是否正在死亡回流。

状态表现可以使用：

- 颜色变化。
- 体型变化。
- 简单粒子。
- 像素动画节奏。
- 小图标提示。
- Debug overlay。

### 11.4 资源流动表现

资源流动最好有轻量可视化：

- 土块发光。
- 小粒子进入怪物。
- 小粒子从怪物回到土中。
- 死亡时周围土块变化。
- 捕食时资源转移提示。
- 勇者死亡时局部资源扩散。

生态游戏最怕“系统存在，但玩家看不到”。

## 12. AI Agent 设计约束

本节供 OpenClaw、Claude Code、Unity MCP 或其他 AI Agent 读取。  
当 AI Agent 参与项目实现时，应优先遵守以下设计约束。

### 12.1 不要把本项目改成普通塔防

禁止倾向：

- 直接放置防御塔。
- 商店购买单位。
- 怪物只作为攻击对象。
- 路径完全固定。
- 土块只作为障碍物。
- 资源只作为 UI 数字。

### 12.2 不要让基础怪物过度智能

基础怪物的行为应保持简单。  
复杂性应来自地形和生态交互。

除非设计文档明确要求，否则不要自动加入：

- A* 全图寻路。
- 远距离目标搜索。
- 玩家直接下达移动命令。
- 自动寻找最优资源点。
- 自动组队攻击勇者。

### 12.3 不要把生态系统写死成单向生产线

错误方向：

```text
挖土 → 生成怪物 → 怪物攻击勇者 → 死亡消失
```

推荐方向：

```text
挖土 → 生成怪物 → 怪物移动/进食/繁殖/死亡
      → 资源在土块与单位之间循环
      → 勇者入侵改变循环
      → 结果影响下一阶段
```

### 12.4 不要过早追求完整数值

早期实现应优先验证系统关系，而不是数值平衡。

优先完成：

- 土块资源存在。
- 挖土影响资源与生成。
- 怪物能移动。
- 怪物能吃或被吃。
- 死亡能回流资源。
- 勇者能入侵。
- 玩家能理解结果。

数值平衡可以后置。

### 12.5 保留 Debug 可视化

AI Agent 实现系统时，应优先提供调试可视化接口或开关。

推荐可视化：

- 土块养分值。
- 土块魔分值。
- 怪物携带资源。
- 怪物目标或当前状态。
- 勇者路径。
- 最近一次资源流动。
- 死亡资源扩散范围。

没有 Debug 可视化，生态系统很难调试。

## 14. 当前项目的推荐方向

### 14.1 项目当前最需要补足的不是怪物数量，而是系统关系

在添加更多怪物之前，应优先确认：

- 土块是否能保存资源？
- 资源是否能影响生成？
- 怪物是否能改变资源？
- 怪物死亡是否有后果？
- 勇者死亡是否反馈到生态？
- 玩家挖掘是否能间接影响上述系统？
- Debug 工具是否能看见这些变化？

如果这些关系不成立，添加再多怪物也只是普通敌人列表。

### 14.2 早期 MVP 应该验证的体验

早期 MVP 不需要完整复刻所有怪物。  
它应该验证以下体验：

- 玩家挖不同土块会得到不同结果。
- 基础怪物会让资源移动。
- 初级消费者会吃掉基础怪物。
- 怪物死亡会让土块资源变化。
- 勇者进入后会破坏生态。
- 击败勇者后地下城获得新资源。
- 玩家能通过挖掘地形改善下一轮结果。

### 14.3 推荐阶段

#### 阶段 1：土块与挖掘

目标：让土块成为资源容器，而不是普通 tile。

#### 阶段 2：基础魔物与资源移动

目标：让低阶单位承担生态功能，而不是战斗功能。

#### 阶段 3：捕食与死亡回流

目标：让食物链和资源循环成立。

#### 阶段 4：勇者入侵

目标：让生态系统接受外部压力测试。

#### 阶段 5：魔分与特殊单位

目标：增加第二套资源逻辑和策略分支。

#### 阶段 6：关卡节奏与教学

目标：让玩家逐步理解生态，而不是一开始就被复杂系统压垮。

## 15. 设计判断清单

每次新增功能前，先检查：

- 这个功能是否强化“地下生态”？
- 它是否让土块更重要？
- 它是否产生资源流动？
- 它是否能被地形间接影响？
- 它是否能被玩家看懂？
- 它是否避免直接 RTS 化？
- 它是否让死亡、捕食或勇者入侵更有意义？
- 它是否有 Debug 可视化需求？
- 它是否会破坏当前最小可行系统？

如果一个功能只是在增加战斗数值，而没有增加生态关系，应暂缓。

## 17. 总结

本项目的核心不是“做很多怪物”，而是构建一个能被玩家通过挖掘间接影响的地下生态系统。

设计优先级应始终保持：

```text
土块资源
→ 资源流动
→ 基础魔物
→ 食物链
→ 死亡回流
→ 勇者入侵
→ 生态反馈
→ 高阶单位与复杂策略
```

当项目没有头绪时，不要先问“再加什么怪物”。  
应该先问：

> 这个新设计能不能让地下生态更清楚、更可控、更容易产生连锁反馈？

只要这个问题成立，项目就仍然沿着正确方向前进。
